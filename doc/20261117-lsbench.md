## 観察点

- 全 29 メソッドで `fail% = 0`、`timeout = 0`。追加した `workspace/diagnostic` と `workspaceSymbol/resolve` も正常に応答しています。
- `diagnostics/open` が 100% empty なのは DummyProject に診断がないためです（エラーではありません）。
- `typeDefinition` / `inlayHint` / hierarchy の展開 / `prepareTypeHierarchy` が 100% null なのは、カーソル位置と対象シンボルの組み合わせによるものです（`fail% = 0`）。
- 最も時間がかかった通常リクエストは `textDocument/completion`（平均 40.6 ms）、次いで `textDocument/codeLens`（平均 9.0 ms）です。
- 修正前は `semanticTokensProvider` が `{"Legend":..., "Range":true, "Full":true}` と PascalCase で広告され、lsbench が provider なしと判定して `textDocument/semanticTokens/full` を Skip していました。UnityCSharpLSP 側で camelCase の `LspSemanticTokensOptions` / `LspSemanticTokensLegend` を導入して修正し、再計測では `--no-skip-unsupported` なしで `textDocument/semanticTokens/full` が実行され、平均 2.83 ms で応答しています。
- `workspace/diagnostic` の p95 は 14.2 ms（1 回の外れ値）、中央値は 1.08 ms です。
